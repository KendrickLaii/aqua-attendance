## 技术方案概述

AQUA 现阶段是出勤 + 教育营运（打卡、班次、月结学费、员工薪资）。以后若做成 ERP（库存、采购、资产），物料主档与课程 SKU 必须分开；学费 Generate 只处理课程行。家具等库存数量与订单件数是两套 quantity。完整正文与阶段表见 **[erp-roadmap.md](erp-roadmap.md)**（本主题 SSOT）。

## 技术选型

| 类别 | 选择 | 理由 |
|------|------|------|
| 语言／框架 | 维持 FastAPI + Vue + PostgreSQL | 不另起 ERP 套件；按阶段加表 |
| 现有学费票 | 保留 `tuition_invoices` 作教育月结 AR | 不急着改名成万能 Invoice |
| 模板 | 不用 Vuexy `/apps/invoice` | 假资料 |

## 架构设计

```
[出勤 / 薪酬]     已上线
[课程 / 月结学费] 已上线  ← Generate 只碰课程行
[items + 库存]    Phase A–B 以后
[采购 AP]         Phase C 以后
[销售行 / 统一 AR] Phase D–E 以后
```

`units` 继续表示能打卡的人；供应商不要塞进 Unit。`unit_type=goods` 不是库存帐。

## 模块划分

| 模块 | 职责 | 依赖 |
|------|------|------|
| 课程 | 开班、报名、堂费／月费 | 现有 `course_*` |
| 教育应收 | 一学生一月一票 | `tuition_invoices` |
| 物料 | 家具等主档 | 新 `items` |
| 库存 | on-hand、入出库 | `stock_*` |
| 采购 | 学校自己买家具 | `suppliers`、PO |

## 接口设计

现阶段不新增 API。Phase A 起再定 `GET/POST /items` 等，见路线图第 6–7 节。

见 [erp-roadmap.md](erp-roadmap.md) §6 草图。不是当前 Alembic。

## 关键设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 家具进 course_skus | 否 | Generate／上课日／报名会错 |
| 学费 Generate | 只产课程行 | 否则库存／销售行被冲掉 |
| 何时开工 | 有真实采购或销售再 Phase A | 空主档会烂 |

## 实现计划

1. Phase 0：学费用稳；不写家具代码。
2. 有需求时 Phase A `items` → B 库存 → C 采购 或 D 销售行（先改 Generate 不删非课程行）。
3. Phase E 再抽统一应收。

待产品确认（Phase D 前）：卖家具是并进该月学费票，还是独立销售发票。
