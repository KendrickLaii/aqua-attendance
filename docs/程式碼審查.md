### 問題清單

#### 🔴 嚴重問題

##### 問題1：本頁無法生成發票

- 位置：`apps/web/src/pages/attendance/courses.vue`（整頁）；attendance API 無 invoice 路由
- 問題：頁面只做科目/開班 CRUD 與「先選學生再報名」。沒有帳單期、發票實體、行項目、已出帳狀態。Vuexy `apps/invoice` 未接到課程報名。
- 風險：若把當前報名表當發票來源，金額、月份、歷史價格都無法保證正確。
- 建議：保留本頁作目錄；新增獨立「Generate invoice」流程（對齊 payroll：選月份 → 按重疊報名拉學生 → 按 SKU 組行項目）。

##### 問題2：價格只存在 SKU 現價，沒有快照

- 位置：`apps/api/app/models/course_sku.py` `price`；報名表無金額欄位
- 問題：發票若直接讀 `course_skus.price`，之後改 A1 學費會改寫歷史帳單。
- 風險：對帳與補印舊月發票錯誤。
- 建議：出帳時把單價、科目名、班次程式碼寫入發票行；報名層可選 `agreed_price`。

##### 問題3：`(unit_id, sku_id)` 永久唯一

- 位置：`apps/api/app/models/course_enrollment.py` `uq_course_enrollment_unit_sku`；`course_enrollments.py` 409
- 問題：同一學生不能再次報名同一班次（下學年 A1）。取消後重報仍衝突，除非刪除舊行。
- 風險：新學期無法報名，或被迫刪歷史導致無法追溯舊發票。
- 建議：唯一約束改為「同一學生同一 SKU 僅一條 active」，或加入學期/學年維度。

#### 🟡 建議修改

##### 問題4：UI 未使用報名起迄日

- 位置：`courses.vue` `enrollStudent()`；API `start_date` / `end_date` 已存在
- 問題：報名只提交 `unit_id` + `sku_id`。無法按「2026-06」過濾誰該繳費。
- 建議：報名表單補開始/結束日期；發票查詢按日期窗口與 `status=active` 過濾。

##### 問題5：報名 UX 是學生優先，且預設 20 人

- 位置：`courses.vue:316-326`、`681-772`
- 問題：海報營運是「這個時段有哪些學生」（班次名冊）。當前是搜尋單個學生。預取 20 名會讓人誤以為名單完整。
- 建議：主視圖改為按 SKU 名冊；學生搜尋保留為次路徑。不要為了發票去一次拉全校學生進下拉框。

##### 問題6：功課輔導班與進修班課時密度不同，卻共用一個 `price`

- 位置：`course_skus.price` + `schedule_note` 自由文本
- 問題：HW1 週一至五每天上課；A1 僅週一。無法從模型推出「6 月多少堂、如何計價」。
- 建議：明確計價單位（月費 / 堂費），或增加 `billing_unit`；不要用 `schedule_note` 做計算。

#### 🟢 可選優化

##### 問題7：學生/報名載入失敗只打 console

- 位置：`courses.vue` `loadStudentOptions`、`watch(selectedStudentId)`

##### 問題8：海報目錄不必重做 UI

- 位置：SPU/SKU 表格

- 薪資只讀 summaries；預設 `unit_type=staff`。月薪 = 整月 `monthly_salary`（不按出勤日折）；時薪 = regular 小時 × 時薪，OT × 倍數。approved／paid 不覆蓋。
- **發現**：`cancelled` 薪資單再 Generate 會被寫回 `calculated`（與學費 void 保留不同）。

#### 課程／學費

- 計價在 SKU。月費 qty 1。堂費 = 上課日 ∩ 該據點香港日出勤；qty 0 跳過。未啟用 SKU 不出帳。一學生一月一票。
- 報名僅 `student`。工作樹：滿員 422、停用班不能新報／不能 PATCH 回 active。HEAD 已禁止新建堂費空上課日。
- 仍接受：#M22 永久唯一、#M23 無假期表、#M24 不發給家長。

#### 人員

- User 才能登入；Unit 才打卡。掃碼與發 QR 看 `is_active`；報名／出學費**不看**學生 `is_active` 或 `status`（graduated 仍可報、仍可出帳）。
- 通知是後臺 inbox，不是家長 WhatsApp。

### 問題清單

#### 🔴 嚴重問題

##### 問題1：員工工時含午休，薪資會多算（#H6，仍在）

- 位置：`apps/api/app/services/overtime.py` `calculate_workday`；`summary_generator.py` 未寫 break
- 問題：9:00–18:00 算 9 小時 regular。手冊與 known-gaps 已標上線前必修，程式碼未改。
- 風險：按 summaries 發工資會多付。
- 建議：按據點固定扣午休槽，或超過 X 小時扣 60 分鐘；寫入 `total_break_minutes`。

#### 🟡 建議修改

##### 問題2：已取消的薪資單會被 Generate 復活

- 位置：`apps/api/app/services/payroll_generator.py`（約 241–260 行）只跳過 `approved`／`paid`
- 問題：`cancelled` 會改回 `calculated` 並重算金額。學費 `void` 無報名則保留。
- 建議：與 tuition 對齊，cancelled 跳過；或 Generate 刪除 cancelled 再決定是否重建。

##### 問題3：薪資「過期彙總」檢測用 UTC 月界，彙總用香港日

- 位置：`detect_stale_summary_units` 用 `datetime(..., tzinfo=timezone.utc)`；`summary_generator` 用 `ATTENDANCE_TZ`
- 問題：月初／月末附近可能誤報或漏報 stale。
- 建議：事件窗口改香港月 1 日 00:00～末日 23:59:59.999999。

##### 問題4：作廢／補登後 summary 與薪資不會自動變（#M16）

- 位置：`POST /api/attendance/{id}/void`、manual
- 建議：void／manual 後重算該人該香港日一條 summary；薪資頁已有 stale 黃條，仍須人手再 Generate。

##### 問題5：已停用／畢業學生仍可報名並出學費

- 位置：`course_enrollments.py` POST 只查 `unit_type==student`；學費 Generate 只過濾報名與 SKU
- 建議：報名要求 `unit.is_active`；Generate 跳過未啟用學生（或產品確認停用仍收尾月學費）。

##### 問題6：無 23:59 排程（#M14）

- 問題：忘記簽退會一直 `checked_in`，隔日第一掃才當新 check_in；未開 AUTO_CHECKOUT 時過去日 Generate 也不補簽退，日彙總 Incomplete。
- 建議：上線前要麼開 flag + cron，要麼營運 SOP 每天 Day-end。UI 須標明手動。
