### 问题清单

#### 🔴 严重问题
**问题1：本页无法生成发票**
- 位置：`apps/web/src/pages/attendance/courses.vue`（整页）；attendance API 无 invoice 路由
- 问题：页面只做科目/开班 CRUD 与「先选学生再报名」。没有账单期、发票实体、行项目、已出账状态。Vuexy `apps/invoice` 未接到课程报名。
- 风险：若把当前报名表当发票来源，金额、月份、历史价格都无法保证正确。
- 建议：保留本页作目录；新增独立「Generate invoice」流程（对齐 payroll：选月份 → 按重叠报名拉学生 → 按 SKU 组行项目）。

**问题2：价格只存在 SKU 现价，没有快照**
- 位置：`apps/api/app/models/course_sku.py` `price`；报名表无金额字段
- 问题：发票若直接读 `course_skus.price`，之后改 A1 学费会改写历史账单。
- 风险：对账与补印旧月发票错误。
- 建议：出账时把单价、科目名、班次代码写入发票行；报名层可选 `agreed_price`。

**问题3：`(unit_id, sku_id)` 永久唯一**
- 位置：`apps/api/app/models/course_enrollment.py` `uq_course_enrollment_unit_sku`；`course_enrollments.py` 409
- 问题：同一学生不能再次报名同一班次（下学年 A1）。取消后重报仍冲突，除非删除旧行。
- 风险：新学期无法报名，或被迫删历史导致无法追溯旧发票。
- 建议：唯一约束改为「同一学生同一 SKU 仅一条 active」，或加入学期/学年维度。

#### 🟡 建议修改
**问题4：UI 未使用报名起迄日**
- 位置：`courses.vue` `enrollStudent()`；API `start_date` / `end_date` 已存在
- 问题：报名只提交 `unit_id` + `sku_id`。无法按「2026-06」过滤谁该缴费。
- 建议：报名表单补开始/结束日期；发票查询按日期窗口与 `status=active` 过滤。

**问题5：报名 UX 是学生优先，且默认 20 人**
- 位置：`courses.vue:316-326`、`681-772`
- 问题：海报运营是「这个时段有哪些学生」（班次名册）。当前是搜索单个学生。预取 20 名会让人误以为名单完整。
- 建议：主视图改为按 SKU 名册；学生搜索保留为次路径。不要为了发票去一次拉全校学生进下拉框。

**问题6：功課輔導班与进修班课时密度不同，却共用一个 `price`**
- 位置：`course_skus.price` + `schedule_note` 自由文本
- 问题：HW1 周一至五每天上课；A1 仅周一。无法从模型推出「6 月多少堂、如何计价」。
- 建议：明确计价单位（月费 / 堂费），或增加 `billing_unit`；不要用 `schedule_note` 做计算。

#### 🟢 可选优化
**问题7：学生/报名加载失败只打 console**
- 位置：`courses.vue` `loadStudentOptions`、`watch(selectedStudentId)`
- 建议：把错误显示到页面，与 `loadError` / `enrollError` 一致。

**问题8：海报目录不必重做 UI**
- 位置：SPU/SKU 表格
- 建议：用 4 个 SPU + 约 20 个 SKU（代码=海报班号）即可。课表可视化可后做。

### 亮点
- SPU/SKU 分层与海报一致：科目（英文/中文/数学/功课辅导）对 SPU，班号（A1、F5）对 SKU。
- 报名 API 已能按 `unit_id` 或 `sku_id` 过滤，班次名册不需要新列表接口。
- 未提交改动里的搜索 requestId 与 `no-filter` 方向正确（服务端搜索），只是「预载 20 人」容易误导。
- Staff payroll 已有「选月份再生成」可复用到学费发票，不必从 Vuexy 假发票抄。

### 结论
- 结论：`Request Changes`
- 严重问题：3 个
- 建议修改：3 个
- 可选优化：2 个
- 下一步建议：先确认计价规则（月费还是堂费、功课辅导是否与 A1 不同价）；再拆两件事——（1）课程页改成班次名册并补起迄日，（2）新做按月生成发票，不要把发票按钮塞进当前 `courses.vue`。
