- User 才能登录；Unit 才打卡。扫码与发 QR 看 `is_active`；报名／出学费**不看**学生 `is_active` 或 `status`（graduated 仍可报、仍可出账）。
- 通知是后台 inbox，不是家长 WhatsApp。

### 问题清单

#### 🔴 严重问题
**问题1：员工工时含午休，薪资会多算（#H6，仍在）**
- 位置：`apps/api/app/services/overtime.py` `calculate_workday`；`summary_generator.py` 未写 break
- 问题：9:00–18:00 算 9 小时 regular。手册与 known-gaps 已标上线前必修，代码未改。
- 风险：按 summaries 发工资会多付。
- 建议：按据点固定扣午休槽，或超过 X 小时扣 60 分钟；写入 `total_break_minutes`。

#### 🟡 建议修改
**问题2：已取消的薪资单会被 Generate 复活**
- 位置：`apps/api/app/services/payroll_generator.py`（约 241–260 行）只跳过 `approved`／`paid`
- 问题：`cancelled` 会改回 `calculated` 并重算金额。学费 `void` 无报名则保留。
- 建议：与 tuition 对齐，cancelled 跳过；或 Generate 删除 cancelled 再决定是否重建。

**问题3：薪资「过期汇总」检测用 UTC 月界，汇总用香港日**
- 位置：`detect_stale_summary_units` 用 `datetime(..., tzinfo=timezone.utc)`；`summary_generator` 用 `ATTENDANCE_TZ`
- 问题：月初／月末附近可能误报或漏报 stale。
- 建议：事件窗口改香港月 1 日 00:00～末日 23:59:59.999999。

**问题4：作废／补登后 summary 与薪资不会自动变（#M16）**
- 位置：`POST /api/attendance/{id}/void`、manual
- 建议：void／manual 后重算该人该香港日一条 summary；薪资页已有 stale 黄条，仍须人手再 Generate。

**问题5：已停用／毕业学生仍可报名并出学费**
- 位置：`course_enrollments.py` POST 只查 `unit_type==student`；学费 Generate 只过滤报名与 SKU
- 建议：报名要求 `unit.is_active`；Generate 跳过未启用学生（或产品确认停用仍收尾月学费）。

**问题6：无 23:59 排程（#M14）**
- 问题：忘记签退会一直 `checked_in`，隔日第一扫才当新 check_in；未开 AUTO_CHECKOUT 时过去日 Generate 也不补签退，日汇总 Incomplete。
- 建议：上线前要么开 flag + cron，要么运营 SOP 每天 Day-end。UI 须标明手动。

#### 🟢 可选优化
**问题7：堂费据点 ≠ 扫描白名单** — SKU 在 A 校、学生扫 B 校，堂费不算。运营要对齐。
**问题8：同楼同日两堂堂费班共用一次打卡** — 设计如此。
**问题9：月费不按日折；报名起迄皆空则每月都出。**
**问题10：SPU `is_active` 不影响 Generate** — 只看 SKU。
**问题11：学生也会生成「工时／OT」汇总** — 薪资默认 staff，但 summaries 页学生会像上班。
**问题12：假日工时栏位从未计算** — `holiday_hours`／`holiday_pay` 恒 0。
**问题13：`units.attendance_status` 可能与事件不一致（#M18）** — void 路径有 recompute，并非所有历史路径都保证。
**问题14：通知不是发给家长的账单通道。**
**问题15：容量／Generate 确认／名册拉全页仍在工作树，未进 `cd71109`。**

### 亮点
- 出勤日一律香港日历；扫描白名单与 unit_type 白名单已落地。
- 工时取首 in／末 out、双扫允许，规则与手册一致。
- 薪资 approved／paid 锁定 + stale 警告，比「静默用旧汇总」好。
- 学费公式（月费／堂费 ∩ 出勤）、draft／void／409 与产品约定一致。037 已在 `cd71109`。
