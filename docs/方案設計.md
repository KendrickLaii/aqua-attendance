## 技術方案概述

AQUA 現階段是出勤 + 教育營運（打卡、班次、月結學費、員工薪資）。以後若做成 ERP（庫存、採購、資產），物料主檔與課程 SKU 必須分開；學費 Generate 只處理課程行。傢俱等庫存數量與訂單件數是兩套 quantity。完整正文與階段表見 **[erp-roadmap.md](erp-roadmap.md)**（本主題 SSOT）。

## 技術選型

| 類別 | 選擇 | 理由 |
| ------ | ------ | ------ |
| 語言／框架 | 維持 FastAPI + Vue + PostgreSQL | 不另起 ERP 套件；按階段加表 |
| 現有學費票 | 保留 `tuition_invoices` 作教育月結 AR | 不急著改名成萬能 Invoice |
| 範本 | 不用 Vuexy `/apps/invoice` | 假資料 |

## 架構設計

```text
[出勤 / 薪酬]     已上線
[課程 / 月結學費] 已上線  ← Generate 只碰課程行
[items + 庫存]    Phase A–B 以後
[採購 AP]         Phase C 以後
[銷售行 / 統一 AR] Phase D–E 以後
```

`units` 繼續表示能打卡的人；供應商不要塞進 Unit。`unit_type=goods` 不是庫存帳。

## 模組劃分

| 模組 | 職責 | 依賴 |
| ------ | ------ | ------ |
| 課程 | 開班、報名、堂費／月費 | 現有 `course_*` |
| 教育應收 | 一學生一月一票 | `tuition_invoices` |
| 物料 | 傢俱等主檔 | 新 `items` |
| 庫存 | on-hand、入出庫 | `stock_*` |
| 採購 | 學校自己買傢俱 | `suppliers`、PO |

## 介面設計

現階段不新增 API。Phase A 起再定 `GET/POST /items` 等，見路線圖第 6–7 節。

## 資料模型

見 [erp-roadmap.md](erp-roadmap.md) §6 草圖。不是當前 Alembic。

## 關鍵設計決策

| 決策點 | 選擇 | 理由 |
| -------- | ------ | ------ |
| 傢俱進 course_skus | 否 | Generate／上課日／報名會錯 |
| 學費 Generate | 只產課程行 | 否則庫存／銷售行被沖掉 |
| 何時開工 | 有真實採購或銷售再 Phase A | 空主檔會爛 |

## 實作計劃

1. Phase 0：學費用穩；不寫傢俱程式碼。
2. 有需求時 Phase A `items` → B 庫存 → C 採購 或 D 銷售行（先改 Generate 不刪非課程行）。
3. Phase E 再抽統一應收。

待產品確認（Phase D 前）：賣傢俱是並進該月學費票，還是獨立銷售發票。

## 技術方案概述

Location Management 的 Photos tab 目前只存 **URL 字串**（`icon_url`、`main_photo_url`、`detail_photos[].url`）。Admin 要自己把圖放到 `http://158…/assets/…` 再貼進來。檔案上傳不應改這套欄位模型：上傳只是「產生一條本系統可託管的 URL」，存進既有欄位。做法是加一個 **admin-only 通用上傳 API**，檔案寫進 **Docker volume 本機磁碟**，再用 FastAPI 公開讀取；Photos tab 改成選檔即傳，並保留「貼外部 URL」作為進階選項。現階段不上 S3 / R2。

## 技術選型

| 類別 | 選擇 | 理由 |
|------|------|------|
| 上傳協議 | `multipart/form-data`（FastAPI `UploadFile`） | `python-multipart` 已在 `requirements.txt`；不要走 JSON base64（稅務附件那套不適合圖片） |
| 儲存 | 本機磁碟 + named volume | 圖很少（中心 logo / 封面），單機 VPS；prod compose 目前沒有物件儲存 |
| 讀取 | `GET /api/uploads/{key}` FileResponse | Caddy 已 `handle /api/*` → API，不必改 Caddyfile |
| DB | **不改 schema** | 繼續存 URL；LocationCard、發票 logo、Mobile 都已讀這些欄位 |
| 物件儲存（S3/R2） | 延後 | Handbook 有寫，但現在為數張圖引入 boto3 / 帳號 / signed URL 過重 |
| 前端元件 | 新建小的 image picker，不重用 `FileUploadZone` | 那是稅務附件 + base64；Location 每格只要一張圖 |

## 架構設計

```text
[Photos tab]
  pick file → POST /api/uploads (Bearer, admin)
           → { url } 寫入 form.icon_url / main_photo_url / detail row
  或繼續貼外部 https://…

[Save location]
  既有 POST/PATCH /api/locations  JSON（URL 字串不變）

[瀏覽器 / 發票 <img>]
  src = 存下來的 URL
  本系統圖：GET /api/uploads/{uuid}.png   （無需登入，檔名不可猜）
  外部圖：  原本的 CDN / assets URL 繼續有效
```

儲存目錄（container 內）：`/data/uploads/{yyyy}/{mm}/{uuid}{ext}`  
Compose 掛 volume，避免 API image 重建後圖消失。

## 模組劃分

| 模組 | 職責 | 依賴 |
|------|------|------|
| `app/services/media_storage.py` | 驗證 MIME/大小、寫檔、組 public URL | 磁碟、`Settings` |
| `app/routers/uploads.py` | POST 上傳、GET 讀檔 | AdminOnly（寫）、公開（讀） |
| `LocationPhotosTab.vue` | 每格：預覽 + 選檔 + 可選貼 URL | `uploadMedia()` |
| 既有 locations API | 不變 | URL 字串 |

## 介面設計

### 介面1：上傳檔案

```
介面名稱：upload media
請求方式：POST
請求路徑：/api/uploads
權限：AdminOnly（Bearer）
Content-Type：multipart/form-data
請求參數：
  - file (UploadFile, 必填): 單一圖片
回應格式：
  {
    "url": "http://host/api/uploads/2026/09/{uuid}.png",
    "key": "2026/09/{uuid}.png",
    "content_type": "image/png",
    "size": 48211
  }
錯誤：
  - 400: 非圖片、副檔名不符、超過大小上限
  - 401/403: 未登入 / 非 admin
```

限制：只收 `image/jpeg`、`image/png`、`image/webp`、`image/gif`；icon 建議 ≤ 2MB，其餘 ≤ 5MB。以 magic bytes 核對，不只信 `Content-Type`。

### 介面2：讀取檔案

```
介面名稱：get uploaded media
請求方式：GET
請求路徑：/api/uploads/{key:path}
權限：公開（不需 Bearer）
回應：image/* FileResponse + Cache-Control: public, max-age=31536000
錯誤：
  - 404: 檔案不存在
  - 400: key 含 `..` 等路徑跳脫
```

公開讀取是因為 `<img src>` 與發票列印 **帶不了 Authorization**。檔名用 UUID，等同不可枚舉。中心 logo 不是個資；若之後上傳學生相片，再改為需登入或 signed URL。

**不要做** `POST /api/locations/{id}/photos`：新建 location 還沒有 id；上傳應與實體脫鉤。Unit `photo_url` 之後可重用同一支 API。

## 資料模型

### 表：locations（不變）

- `icon_url` (varchar 500): 列表小圖
- `main_photo_url` (varchar 500): 封面
- `detail_photos` (json): `[{ url, caption, sort_order }]`

### 設定（新增，無 migration）

```
UPLOAD_DIR          default /data/uploads
UPLOAD_MAX_BYTES    default 5_242_880
PUBLIC_BASE_URL     可選；未設則用 request.base_url（Caddy 反代後的 Host）
```

### 前端 form（不變）

仍是字串 URL。選檔成功後把回傳 `url` 寫進對應欄位；預覽繼續用 `VImg :src`。

## 關鍵設計決策

| 決策點 | 選擇 | 理由 |
|--------|------|------|
| URL vs 檔案 FK | 繼續存 URL | 零 schema 變更；外部圖與本系統圖可並存 |
| 何時上傳 | 選檔後立刻 POST | 新建 location 可先拿 URL 再 Save；不必「先建再傳」兩步 |
| 本機 vs S3 | 先本機 volume | 圖量極小；S3 等真的要多機或備份策略再抽 `MediaStorage` |
| 讀取要不要登入 | GET 公開 | img / 列印不能帶 token |
| 取代舊圖時刪檔 | v1 不刪 | 避免誤刪共用 URL；接受少量 orphan |
| Tax `FileUploadZone` / base64 | 不用 | payload 肥、無法快取、與出勤 API 風格不合 |
| 貼 URL | 保留，收進「進階」 | 現有 `…/assets/wl_logo2…` 不必重傳 |

## 實作計劃

1. API：`MediaStorage` + `POST/GET /api/uploads` + 測試（類型/大小/路徑跳脫/admin 才能寫）。
2. Compose：`uploads` volume 掛到 API `/data/uploads`（dev + prod）。
3. Web：`uploadMedia(file)`；Photos tab 每格改為預覽 + Upload + Remove，URL 欄可摺疊。
4. 拿掉「Photos use external URLs in v1」提示。
5. （可選後續）Unit `photo_url` 同一套 picker；再之後才接 R2。

風險：API container 若沒掛 volume，重佈署圖會丟（URL 變 404）。這是必做項，不是可選。Caddy 後的 `request.base_url` 若 Host 不對，補 `PUBLIC_BASE_URL`。
